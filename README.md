# 🏪 نظام بيع وجرد لمحل مستحضرات التجميل (Cosmetics POS & Inventory System)

> برنامج ويندوز ديسكتوب يعمل بالكامل **أوفلاين 100%** على جهاز المحل، مبني وفق أعلى معايير الأمان وسرعة البيع بالباركود وإدارة الصلاحية (FEFO).

## ☁️ إعداد الميزات السحابية (Cloud features setup)

ميزات الاتصال السحابي (التحقق من التراخيص، والنسخ الاحتياطي المشفر) هي ميزات **إضافية واختيارية تماماً**. يظل البرنامج يعمل بنسبة 100% أوفلاين دون الحاجة لأي اتصال بالإنترنت أو خادم سحابي.

### 1. ما يتم إنشاؤه في Supabase (Database & Storage)

1. **جداول قاعدة البيانات وسياسات الأمان (RLS):**
   - جدول `licenses`: يضم بيانات الترخيص، اسم العميل، معرف الجهاز المربوط (`machine_id`)، الميزات المصرح بها (`features: text[]`)، تاريخ انتهاء التحديثات (`updates_until`)، وحالة الترخيص (`status`).
   - جدول `backups`: يضم سجلات النسخ السحابية التابعة لكل ترخيص وحجمها ومسارها.
   - تفعيل سياسات الأمان الصارمة (Row Level Security): منع أي وصول مباشر أو قراءة أو حصر لبيانات أي عميل آخر من قِبل أي عميل عبر الـ Anon Key.
2. **وحدة التخزين السحابي الخاصة (Private Storage Bucket):**
   - إنشاء الحاوية الخاصة `backups` مع تعطيل الوصول العام (`public = false`).
   - كل ملف يتم حفظه في مجلد خاص بالترخيص: `backups/{license_id}/{timestamp}_{filename}`.
   - التحميل والرفع يتم حصراً بروابط موقعة مؤقتة (Short-lived Signed URLs).
3. **دوال الحافة (Supabase Edge Functions):**
   - `verify-license`: فحص الترخيص، ربطه بالجهاز، وإرجاع الصلاحيات.
   - `create-backup-upload-url`: التحقق من ميزة `cloud_backup`، وتدوير النسخ القديمة (إبقاء آخر 7 نسخ)، وإرجاع رابط رفع موقّع.
   - `list-backups`: استعراض النسخ الخاصة بالترخيص الحالي فقط.
   - `get-backup-download-url`: توليد رابط تحميل موقّع لنسخة محددة بعد التأكد من الملكية.

### 2. المتغيرات المطلوبة في تطبيق الديسكتوب (`.env`)

أنشئ ملف `.env` في المجلد الرئيسي للتطبيق (وهو مدرج ومستبعد في `.gitignore`):

```env
SUPABASE_URL=https://your-project-id.supabase.co
SUPABASE_ANON_KEY=your-actual-anon-public-key
```

> [!CAUTION]
> **قاعدة أمان صارمة:** لا تقم إطلاقاً بوضع مفتاح `service_role` داخل ملف `.env` أو في كود التطبيق المكتبي نهائياً.

### 3. الأسرار والمفاتيح في خوادم Supabase (Supabase Secrets)

يتم ضبط مفتاح `service_role` حصراً داخل أسرار دوال الحافة في لوحة تحكم Supabase:

```bash
supabase secrets set SUPABASE_SERVICE_ROLE_KEY=your-supabase-service-role-key
```

### 4. دليل الاختبار والتحقق اليدوي (Testing & Verification Checklist)

1. **التشغيل عند غياب ملف `.env` (Missing .env):**
   - احذف ملف `.env` أو اتركه فارغاً وشغل التطبيق.
   - يجب أن يقلع التطبيق فوراً بدون أي شاشات خطأ أو انهيار. تظهر شاشة الإعدادات أن السحابة معطلة محلياً والـ POS يعمل بكفاءة 100%.
2. **التشغيل الأوفلاين التام (Offline Start):**
   - افصل كابل الإنترنت أو أوقف الـ Wi-Fi وشغل التطبيق.
   - يفتح التطبيق فوراً ويعتمد الحالة المحفوظة محلياً في SQLite دون أي تأخير أو تعليق.
3. **أخذ نسخة سحابية مشفرة (Cloud Backup):**
   - من شاشة الإعدادات -> تبويب "الخدمات السحابية والترخيص"، أدخل معرف الترخيص واضغط "تحقق وتفعيل".
   - اضغط "أخذ نسخة سحابية الآن".
   - يتم أخذ لقطة ذرية بـ `VACUUM INTO`، ثم ضغطها بـ Gzip، ثم تشفيرها بـ AES-256-GCM، ورفعها بنجاح إلى السحابة وظهورها في الجدول.
4. **استعادة نسخة سحابية (Cloud Restore):**
   - اضغط على "استعادة" بجانب إحدى النسخ في الجدول.
   - تظهر نافذة تأكيد واضحة توضح أخذ نسخة أمان محلية قبل الاستبدال.
   - بعد التأكيد، يتم تنزيل الملف، فك تشفيره، فحص سلامة الـ SQLite عبر `PRAGMA integrity_check`، استبدال الملف، وإعادة تشغيل التطبيق.
5. **الترخيص الملغي وفترة السماح (Revoked License & Grace Period):**
   - عند إلغاء الترخيص على السحابة، يبدأ التطبيق فترة سماح (Grace Period) مدتها 30 يوماً تظهر بوضوح في الواجهة.
   - بعد انقضاء الـ 30 يوماً تتعطل الخدمات السحابية الإضافية، بينما تظل وظائف البيع المحلي ونقطة البيع (POS) والمخزون والصيانة تعمل دون أي توقف نهائياً.
